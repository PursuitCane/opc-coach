# 技术亮点

> 面向 BP / 路演的技术叙事。对应大纲「解决方案 → 技术亮点」一节。
> 一句话：通用 AI 是无状态的一次性问答；我们的工程本质，是把杂乱对话变成一个可推理、可演进、可被真实结果校准的"生意模型"。
> Tag: `#shenicest-fission`

## 核心判断

产品的技术护城河不在"接了大模型"，而在两件通用 AI 结构性做不到的事：

- 它没有状态 —— 记不住你的生意长什么样、上次赌的假设验证了没。
- 它没有反馈信号 —— 永远不知道自己给的建议在真实世界里成没成。

我们的两大技术亮点，正是补上这两块：**商业状态图谱**解决"状态"，**决策闭环反馈回路**解决"反馈"。前者是数据资产的载体，后者是让 coach 自我进化的燃料——两者共同构成难以复制的数据飞轮。

---

## 亮点一：商业状态图谱（Business State Graph）

> 对应 BP 的"长期 Memory / 记得你为什么做过这些决定"，但底层不是"存聊天记录"，而是一张活的、带版本的生意知识图谱。

**是什么**
我们为每个 Founder 的生意建一张持续演进的图谱：节点是「假设 / 决策 / 行动 / 结果」，边是它们之间的因果与时序关系。对话不再是一串消息，而是被结构化地"喂"进这张图——每一句"我觉得用户会为 X 付费"都会落成一个可追踪的假设节点，并进入自己的生命周期：提出 → 验证中 → 证实 / 证伪。

**关键工程**
- 结构化抽取：从自由对话中识别并抽取领域实体与关系（假设、决策、指标、竞品……），把非结构化输入转成可查询的图。
- 信念修正（belief revision）：Founder 前后口径变了——上月 TAM 说 X、这月改成 Y——系统做的是覆盖与版本化，而非叠加冲突，保证图谱始终自洽。
- 状态机管理：每个假设按状态机推进，系统随时能回答"哪些假设还悬着、哪些已被结果证伪"。
- 结构化检索：新一轮判断时，按相关度 + 时序召回图谱里相关的历史决策与结果，而不是全量回灌聊天记录。

**为什么是壁垒**
存聊天记录做 RAG 谁都会；存一个"能推理生意状态"的状态机很难。这张图谱是「假设—决策—行动—结果」数据资产的物理载体——它越完整，coach 越懂你的生意，也越难被复制。

**对用户的价值**
让每一次新决策都建立在你过去真实的判断、实验和结果之上，而不是每次从零讲背景。第一次它是陌生投资人，第十次是懂你项目的老搭档。

## 亮点二：决策闭环反馈回路（Decision-Loop Feedback）

> 对应 BP 的"harness 自进化 / 数据飞轮"，也是北极星指标"每日 ≥1 个有效决策闭环"的技术实现。

**是什么**
自进化只有在拿到可靠反馈信号时才成立，否则是空话。信号从哪来？就是决策闭环本身：系统检测到一个决策 → 主动追着要结果回填 → 把 `(商业上下文 → 决策 → 真实结果)` 沉淀成评估数据 → 用它反过来校准 coach 的提问、打分与建议策略。

**关键工程**
- 决策检测：从对话中识别"这是一个真正的决策点"，并挂到状态图谱对应节点。
- 结果回填机制：这是整条回路的命门——通过到期提醒、轻量回填交互、把回填做成陪跑的自然一环，尽可能拉高结果回填率（没有回填，飞轮就是空转）。
- 归因与 Eval：把决策结果作为标注信号，评估"当初那次追问 / 判断是否真的推动了好结果"，形成可度量的 coach 表现评估体系。
- 策略迭代：基于 eval 信号优化提问路径与诊断策略，让评估框架在使用中被真实结果打磨，而不是写死的模板。

**为什么是壁垒**
这条回路产出的是一份别人拿不到的资产：**真实的「决策—结果」标注数据集**。通用 LLM 永远不知道"这个建议在现实里成没成"，我们知道。产品跑的真实决策越多，coach 越准——这就是数据飞轮的物理实现，也是随规模累积、难以被简单复制的长期壁垒。

**对用户的价值**
今天的军师比昨天更准。你的每一次决策与结果，既在优化你自己的判断，也在让这个 coach 对所有 Founder 更有用。

## 支撑层（围绕上面两大核心）

这三块是好工程，但属于"投入就能做"，是为上面两大亮点服务的编排层，路演时不平均用力：

- **优先级引擎（该做什么）**：对图谱里未验证的假设按 `影响度 × 不确定性 × 验证成本` 打分排序，回答 BP 痛点 2"现在最该做什么"。苏格拉底式追问 challenge 什么，是这个排序的输出，不是随机反问；有了分数，系统也知道何时该怼、何时该给正反馈（张弛机制）。
- **Skill 编排 harness（平台化）**：专家 Skill Marketplace 的技术实现——skill 注册表 + 路由器，按图谱当前缺口（缺 PMF 判断 / 融资准备度 / 定价模型）分派给对应专业 skill，每个 skill = prompt + 工具 + 知识库 + 自己的 eval。
- **可信 challenge 的 grounding 管线**：接搜索 + 行业数据 RAG + 可比公司 benchmark，challenge 时带证据与引用，让"有立场"不等于"嘴硬"。

## 诚实标注（demo vs roadmap）

- 真正难抄的是亮点一、二（状态图谱 + 结果反馈数据集），叙事重心应压在这两块。
- Demo 阶段可做出可见证据的：状态图谱的抽取与可视化、grounding 带引用的 challenge。
- 更偏架构 / roadmap 的：结果反馈回路的完整自进化、skill 路由——建议讲成"设计中的机制"，避免与 demo 对不上被追问。

## 一句话收尾（路演可用）

我们把一门生意变成一个可推理的状态机，再用真实的决策结果不断校准它——不是一个 AI 点评插件，而是一个会随你成长、并把整个决策过程沉淀成数据资产的商业军师。
